## 介绍

&emsp;&emsp;平台新增内部测试的代码审计功能，上传zip等格式的项目文件，可以自定义审计规则和审计平台，前端展示审计日志的结果，登录后可查询历史并提供导出功能。

功能一：上传文件，支持多种格式上传如zip，7z等格式。

功能二：自定义审计规则和审计平台，依赖前端实现。

功能三：展示审计日志的结果。后端使用策略设计模式，通过调用不同的API，实现代码审计服务，审计日志存储到数据库中。当前查看和历史查看都从数据库中查询数据。
    
功能四：可根据日期批量导出审计日志，项目文件内的导出功能直接发送excel，批量导出功能打包为zip格式发送。

## 3、深分页优化

&emsp;&emsp;当需要查询数据库中靠后的字段，时间会很漫长，十万级别需要500ms左右，百万级别需要30秒，千万级别需要分钟。原因是二级索引会查询所有的行（offset+count），然后进行全部的回表操作，主键索引扫描offset+count行，抛弃offset行返回count行数据。

&emsp;&emsp;常见三种优化方式：

&emsp;&emsp;①子查询优化
```SQL
select * from table where id > （select id …）limit 10
--通过子查询找到主键（id字段），减少回表次数
```
&emsp;&emsp;优点：十万级别的偏移量耗时50ms左右；子查询只需要ID列，减少数据传输；可以根据业务动态调整分页参数，提高灵活性

&emsp;&emsp;缺点：索引依赖；子查询结果集很大，也会影响性能；MySQL5.6之前不支持子查询使用limit，解决方案是升级数据库、改用join、外层再套一层查询。

&emsp;&emsp;②延迟关联

&emsp;&emsp;利用join字段，性能同子查询优化，核心思想利用索引覆盖。只需要回表join里的子表数量。

&emsp;&emsp;③书签优化

&emsp;&emsp;记录上一次查询的最大ID，下次查询从记录开始

&emsp;&emsp;优点：查询时间极度缩减，十万级别10毫秒完成

&emsp;&emsp;缺点：不能跳页查询；依赖递增主键或者字段

&emsp;&emsp;适用场景：资讯类APP的瀑布流

```java
@Service
@RequiredArgsConstructor
public class ItemQueryService {
    private final ItemMapper itemMapper;
    
    // 分页结果封装类
    @Data
    @AllArgsConstructor
    public static class PageResult {
        private List<Item> items;
        private Long nextLastId; // 下一页的书签ID
        private Boolean hasMore; // 是否还有更多数据
    }
    
    public Object queryItems(Long projectId, Long userId, Long lastId, Integer pageSize) {
        // 参数校验
        if (projectId == null || userId == null) {
            throw new IllegalArgumentException("项目ID和用户ID不能为空");
        }
        pageSize = (pageSize == null || pageSize <= 0) ? 100 : Math.min(pageSize, 500);
        
        // 获取总条数并判断是否超过1w
        long totalCount = itemMapper.countByProjectAndUser(projectId, userId);
        if (totalCount <= 10000) {
            return itemMapper.selectAllByProjectAndUser(projectId, userId);
        }
        
        // 大数据量使用书签分页
        List<Item> items;
        if (lastId == null) {
            items = itemMapper.selectFirstPage(projectId, userId, pageSize);
        } else {
            items = itemMapper.selectByPageWithBookmark(projectId, userId, lastId, pageSize);
        }
        
        // 计算是否有更多数据
        boolean hasMore = items.size() >= pageSize;
        Long newLastId = items.isEmpty() ? null : items.get(items.size() - 1).getId();
        
        return new PageResult(items, newLastId, hasMore);
    }
}
```

```java
public class ThreadPoolConfig {

    @Bean(name = "exportProjectExecutor")
    public ThreadPoolExecutor projectExecutor() {
        return new ThreadPoolExecutor(
            exportConfig.getProjectCoreThreads(),
            exportConfig.getProjectMaxThreads(),
            exportConfig.getKeepAliveTime(),
            TimeUnit.SECONDS,
            new LinkedBlockingQueue<>(exportConfig.getQueueCapacity()),
            new NamedThreadFactory("export-project-"),

            new ThreadPoolExecutor.CallerRunsPolicy());
    }

    @Bean(name = "exportCodingExecutor")
    public ThreadPoolExecutor codingExecutor() {
        return new ThreadPoolExecutor(
            exportConfig.getCodingCoreThreads(),
            exportConfig.getCodingMaxThreads(),
            exportConfig.getKeepAliveTime(),
            TimeUnit.SECONDS,
            new LinkedBlockingQueue<>(exportConfig.getQueueCapacity()),
            new NamedThreadFactory("export-coding-"),
            // 拒绝策略是直接抛弃
            new ThreadPoolExecutor.AbortPolicy());
    }

    @RequiredArgsConstructor
    private static class NamedThreadFactory implements ThreadFactory {
        private final String namePrefix;
        private final AtomicInteger threadNumber = new AtomicInteger();
        
        public NamedThreadFactory(String namePrefix){
            this.namePrefix = namePrefix;
        }

        @Override
        public Thread newThread(Runnable r) {
            Thread t = new Thread(r);
            t.setName(namePrefix + threadNumber.incrementAndGet());
            return t;
        }
    }
}
```

线程池要点：

用ThreadPoolExecutor创建线程池，因为Executors用的是无界队列，会有OOM风险。

线程池调度线程有两种方式，Runnable和Callable，execute和submit。Callable可以抛出异常，submit返回一个Future对象，可以知道是否执行成功和处理异常。

Workqueue有无界队列、同步队列、延迟阻塞队列

```java
// 分级多组导出实例
@Service
@RequiredArgsConstructor
@Slf4j
public class DataExporter {
    private final DataMapper dataMapper;
    private final ExportTaskStore taskStore;
    private final CheckpointManager checkpointManager;
    private final FileCompressor fileCompressor;
    private final ExportValidator validator;
    
    @Qualifier("exportProjectExecutor")
    private final ThreadPoolExecutor projectExecutor;
    
    @Qualifier("exportCodingExecutor")
    private final ThreadPoolExecutor codingExecutor;

    public String startExport() {
        String taskId = UUID.randomUUID().toString();
        ExportTask task = new ExportTask();
        task.setTaskId(taskId);
        task.setStatus("RUNNING");
        task.setStartTime(new Date());
        taskStore.save(task);
        
        //任务管理队列异步处理不同的任务
        CompletableFuture.runAsync(() -> {
            try {
                executeExport(task);
            } catch (Exception e) {
                log.error("导出任务失败", e);
                task.setStatus("FAILED");
                taskStore.save(task);
            }
        }, projectExecutor);
        
        return taskId;
    }

    private void executeExport(ExportTask task) {
        List<String> projectIds = dataMapper.selectDistinctProjectIds();
        task.setTotalProjects(projectIds.size());
        
        CountDownLatch projectLatch = new CountDownLatch(projectIds.size());
        AtomicInteger successCount = new AtomicInteger(0);
        
        for (String projectId : projectIds) {
            if (checkpointManager.isProcessed(task.getTaskId(), projectId)) {
                projectLatch.countDown();
                continue;
            }
            
            // 第一级projectExecutor
            projectExecutor.execute(() -> {
                try {
                    exportProject(task.getTaskId(), projectId);
                    successCount.incrementAndGet();
                    checkpointManager.markProcessed(task.getTaskId(), projectId);
                } finally {
                    projectLatch.countDown();
                }
            });
        }
        
        // 通过task管理，实现进度追踪、压缩、校验、中断恢复、耗时计算
        try {
            // await确保所有project都被导出成功
            projectLatch.await();
            task.setCompletedProjects(successCount.get());
            
            if (exportConfig.isEnableCompression()) {
                String zipPath = fileCompressor.compress(task.getTaskId());
                task.setResultZipPath(zipPath);
            }
            
            if (exportConfig.isEnableValidation()) {
                validator.validate(task.getTaskId());
            }
            
            task.setStatus("COMPLETED");
            task.setEndTime(new Date());
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            task.setStatus("PAUSED");
        } finally {
            taskStore.save(task);
        }
    }

    private void exportProject(String taskId, String projectId) {
        String workbookPath = exportConfig.getBaseDir() + "/" + taskId + "/project_" + projectId + ".xlsx";
        ExcelWriter excelWriter = EasyExcel.write(workbookPath).build();
        
        try {
            List<String> codingIds = dataMapper.selectDistinctCodingIds(projectId);
            CountDownLatch codingLatch = new CountDownLatch(codingIds.size());
            
            for (String codingId : codingIds) {
                codingExecutor.execute(() -> {
                    try {
                        exportCodingData(projectId, codingId, excelWriter);
                    } finally {
                        codingLatch.countDown();
                    }
                });
            }
            
            codingLatch.await();
        } catch (Exception e) {
            log.error("Project {} 导出失败", projectId, e);
            throw new RuntimeException(e);
        } finally {
            excelWriter.finish();
        }
    }
    
        private void exportCodingData(String projectId, String codingId, ExcelWriter excelWriter) {
        WriteSheet writeSheet = EasyExcel.writerSheet("coding_" + codingId).build();
        int offset = 0;
        
        try {
            while (true) {
                List<DataModel> batch = dataMapper.selectDataBatch(
                    projectId, codingId, offset, excelConfig.getBatchSize());
                
                if (batch.isEmpty()) break;
                
                // 单独的sheet上锁保证并发下不出现问题
                synchronized (excelWriter) {
                    excelWriter.write(batch, writeSheet);
                }
                
                offset += excelConfig.getBatchSize();
            }
        } catch (Exception e) {
            log.error("导出失败 - project: {}, coding: {}", projectId, codingId, e);
            throw new RuntimeException("导出失败", e);
        }
    }
}
```

```java
// 动态调整线程池
@Service
@RequiredArgsConstructor
public class ThreadPoolMonitorService {
    private final ThreadPoolExecutor projectExecutor;
    private final ThreadPoolExecutor codingExecutor;
    
    @Scheduled(fixedRate = 5000) // 每5秒检查一次
    public void adjustThreadPools() {
        double systemLoad = getSystemLoadAverage();
        int projectThreads = calculateOptimalThreads(projectExecutor, systemLoad);
        int codingThreads = calculateOptimalThreads(codingExecutor, systemLoad);
        
        projectExecutor.setCorePoolSize(projectThreads);
        codingExecutor.setCorePoolSize(codingThreads);
    }
    
    private double getSystemLoadAverage() {
        // 查看JVM运行状态
        return ManagementFactory.getOperatingSystemMXBean().getSystemLoadAverage();
    }
    
    private int calculateOptimalThreads(ThreadPoolExecutor executor, double systemLoad) {
        int current = executor.getCorePoolSize();
        if (systemLoad > 3.0) { // 高负载时减少线程
            return Math.max(1, current - 2);
        } else if (systemLoad < 1.0) { // 低负载时增加线程
            return Math.min(executor.getMaximumPoolSize(), current + 2);
        }
        return current; // 保持现状
    }
}
```

### 1、为什么用雪花算法？雪花有什么缺点？或者问怎么保证没有重复数据？

如果用数据库自增主键，那么在分库分表之后就无法再根据ID查找，十分不方便；并且每次获取ID都需要访问数据库，速度慢，增加数据库压力。

如果用UUID的话，因为UUID比较大（32个16进制数字），一行的数据就会变多，影响数据库性能；并且是无序的，会触发数据库的页分裂，一般业务还是需要趋势递增的方便查找。

雪花的缺点一是时间回拨问题，参考美团的leaf-snowflake算法，解决方案是等待一会儿，时间可能就恢复了，如果没有恢复就上报警告。注意，leaf算法用到zookeeper来生成机器序列号，因为美团业务是大集群，如果是小集群可以手动配置。

二是序列号为0的问题，因为序列号是在高并发的时候才会触发，所以很有可能都为0，那么在取模分表等业务就很不方便，解决思路是取时间戳那一部分的尾数，这样就可以有奇数和偶数。

设计字段是时间戳+代码文件的hash值+序列号（同一份代码文件可能多次提交审计）接入第二个平台后，借一位序列号作为区分度。

### 2、幂等性设计

多次提交只返回一个相同的结果，数据库主键约束能保证重复提交只有一条记录被保存在数据库。
一定程度解决了数据库死锁的问题，因为不会出现重复的订单。

常见的死锁出现在间隙锁上，如果事务A要插入数据，就会在上下两条数据之间插入间隙锁，此时事务B也恰好在这个之间插入数据，也会生成间隙锁。然后AB都要拿到插入意向锁才能插入数据，但插入意向锁和间隙锁是互斥的（注意，间隙锁和间隙锁不互斥），所以形成死锁。

延伸问题：为什么幂等性做了数据库主键约束，还需要雪花ID？

雪花ID还能解决分布式的并发问题。

### 3、分库分表的注意事项，分片键应该如何选取？数据库的量级？

数据库一般千万级别需要分表，单表大小2-4G左右。一个月的数量为千万级别，之前是一个月一张表，接入第二个平台后，单表过于庞大，于是基于此产生了分表的需求。现在的单表按照天来划分，表名是年月日，表内字段有雪花ID，用户ID，代码文件的hash值，现在单表大小为100W，日均增长100w（之前日增长50w），月增长3000w。

常见分表算法有哈希分片算法，范围分片算法（按照时间划分）。

### 4、选用什么隔离级别？为什么这么选？

选用RC级别，RC适合对一致性有要求，同时兼顾高并发性能的级别，例如查询订单状态；RR级别对一致性要求较高，例如银行转账对账

RC和RR的实现都是基于锁+MVCC，区别在于生成read view的时机。RC在每次select语句都会重新生成read view，所以无法解决不可重复读的问题；RR只在事务开启的时候生成一次read view，所以保证了整个事务期间都只有一个状态。

此外，select语句是快照读，RR通过MVCC就能解决幻读问题；select..for update是当前读，RR通过临键锁（next-key lock）在事务之间加锁。注意，一定要走索引，不然会触发全表扫描。
实际开发中一般都使用RC级别。
